# Runbook

## Що це

Бот сам вигадує англійську ідіому чи колокацію, пише живе пояснення
українською (стиль Hot Idioms — з характером, без мату), підбирає
реакцію-гіфку за змістом/настроєм фрази і приносить готовий пост тобі в
приват. **У канал нічого не потрапляє без ✅.**

Пост — гіфка (з підпису GIPHY, `mp4` або `gif`) з підписом: фраза,
пояснення, приклад із перекладом. Гіфку шукає AI за ключовим словом настрою
(наприклад для «cut corners» — «lazy shortcut»), а не буквальним
промовлянням фрази у відео — це навмисно: реакція-гіфка передає емоцію
краще, ніж уривок мовлення, і не тягне жодних юридичних питань про
перезаливання чужого відео. Якщо GIPHY нічого не знайшов — картка виходить
текстовою на градієнтному тлі, пост усе одно публікується.

## Перший запуск

### 1. Ключі

Скопіюй `.env.example` в `.env` і заповни:

| Змінна | Де взяти | Вартість |
|---|---|---|
| `BOT_TOKEN` | [@BotFather](https://t.me/BotFather) → `/newbot` | 0 |
| `CHANNEL_ID` | створи канал, додай бота адміном із правом постити | 0 |
| `ADMIN_IDS` | свій id: напиши [@userinfobot](https://t.me/userinfobot) | 0 |
| `GEMINI_API_KEY` | [aistudio.google.com](https://aistudio.google.com/apikey) | безкоштовний тариф вистачає |
| `GIPHY_API_KEY` | [developers.giphy.com/dashboard](https://developers.giphy.com/dashboard/) → Create App | 0, реєстрація за хвилину |

GIPHY-ключ дають миттєво після простої форми — жодного очікування
схвалення на такому обсязі використання.

### 2. Локально (Windows)

Проєкт має власне venv — глобальний Python не чіпаємо, щоб не зачепити
сусідні проєкти (у них інші версії aiogram та aiohttp).

```bash
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt -r requirements-dev.txt
.venv\Scripts\python -m app.tools.smoke --phrase "bite the bullet" --no-ai
```

`--no-ai` підставляє текст-заглушку, тож перевіряє пошук гіфки й підпис без
звернень до Gemini. Готовий файл (mp4/gif/png) зʼявиться в `data/media/`.

Коли картка виглядає добре — повний прогін і запуск бота:

```bash
.venv\Scripts\python -m app.tools.smoke --phrase "spill the beans"
.venv\Scripts\python -m app.main
```

### 3. На VPS

```bash
docker compose up -d --build
docker compose logs -f bot
```

Спершу постав `CHANNEL_ID` на **приватний тестовий канал**. Коли пости
влаштовують — заміни на бойовий і `docker compose up -d`.

Розгортання тепер гранично просте: жодних сторонніх сервісів у
`docker-compose.yml`, жодного `ffmpeg` в образі — тільки бот і GIPHY по
HTTPS.

## Щоденна робота

| Команда | Що робить |
|---|---|
| `/queue` | черга: схвалені, на ревʼю, без гіфки |
| `/schedule` | слоти публікації, розмір черги, пауза |
| `/add spill the beans` | пост із конкретної фрази поза чергою |
| `/stats` | лічильники за статусами |
| `/pause` | пауза й зняття паузи |

Кнопки під карткою: **✅ Схвалити** (стає в найближчий слот), **✏️ Змінити
текст**, **🔄 Перегенерувати** (можна з коментарем), **🎬 Інша гіфка**,
**🔍 Кандидати**, **🕑 Перенести**, **❌ Відхилити**.

Слот без схваленого поста просто проходить — канал мовчить. За годину до слота
бот нагадає, якщо публікувати нічого.

## Коли щось ламається

### GIPHY повертає 403 «BANNED» або 0 результатів

Публічний демо-ключ GIPHY (`dc6zaTOxFJmzC` з їхніх прикладів) віддає
`{"msg": "BANNED"}` — його роками експлуатували в демках, і GIPHY зрештою
заблокував. Потрібен **власний** ключ у `GIPHY_API_KEY`, це безкоштовно й
миттєво: [developers.giphy.com/dashboard](https://developers.giphy.com/dashboard/).

Порожній список (`data: []`) при робочому ключі зазвичай означає, що
`gif_query` від AI занадто специфічний або дивний — подивись, що саме
запитувалось:

```bash
.venv\Scripts\python -m app.tools.smoke --phrase "some phrase" --find-only
```

### GIPHY недоступний узагалі (мережа, ключ не працює)

Пост не зупиняється: `attach_media` у `app/pipeline.py` після невдалих
спроб сам падає на `render_card` — текстову картку на градієнтному тлі
(`app/media/render.py`). Це видно в підписі як `awaiting_media`-статус,
що знято, і зауваження в тексті «Гіфку не знайшли — картка текстова».

### Gemini віддає 503 або 429

Нормальна поведінка безкоштовного тарифу, і вона прив'язана до конкретної
моделі: `gemini-3.8-flash` може бути перевантажена, а `gemini-3.6-flash` у ту
саму секунду відповідає. Тому в коді два рівні захисту:

1. **Ретраї** — 5 спроб із подвоєнням паузи (2, 4, 8, 16 с).
2. **Запасні моделі** — `AI_MODEL_FALLBACKS` у `.env`. Коли основна вичерпала
   спроби, робота переходить до наступної.

Побачити, які моделі доступні саме твоєму ключу:

```bash
.venv\Scripts\python -c "from google import genai; from app.config import settings; [print(m.name) for m in genai.Client(api_key=settings.gemini_api_key).models.list()]"
```

Якщо 429 сипле постійно — підключи білінг у Google AI Studio, ліміти піднімуться.

### Атрибуція GIPHY

Умова їхнього безкоштовного API — видима позначка «Powered by GIPHY».
`app/content.py` додає її автоматично як посилання на сторінку гіфки в
кінці підпису, коли пост має справжню гіфку (не текстовий фолбек). Прибирати
цей рядок не можна — це порушення умов використання API.

## Архітектура

```
app/media/giphy.py   пошук реакції-гіфки за gif_query через GIPHY API
app/media/render.py  Pillow: текстова картка-фолбек, коли гіфки нема
app/pipeline.py      оркестрація: фраза → текст (+ gif_query) → гіфка → черга
app/ai/schemas.py    PostContent.gif_query — AI сам підбирає ключове слово
```

Ніякого YouTube, yt-dlp чи ffmpeg у системі більше нема: попередня версія
шукала буквальне промовляння фрази в субтитрах і вирізала кадр із відео —
працююче, але вразливе до бот-стіни YouTube рішення. GIPHY стабільніший,
офіційно дозволений для цього й не має нічого спільного з відео-контентом
взагалі.

## Де що лежить

```
app/ai/          промпти й генерація тексту (Gemini, structured outputs)
app/media/       пошук гіфки (GIPHY) і текстова картка-фолбек (Pillow)
app/bot/         картка ревʼю, кнопки, команди
app/pipeline.py  оркестрація: фраза → текст → гіфка → черга
app/scheduler.py фонові задачі
app/slots.py     розрахунок часу публікації
data/            SQLite і готові медіафайли (data/media/, том у Docker)
```

Схема БД створюється сама через `create_all` — міграцій нема. Щоб почати з
нуля: зупини бота й видали `data/channel.db`.
